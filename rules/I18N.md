# Workstation i18n & Localization Guardrails

## 1. Single Source of Truth (SSOT)
- **Supported Languages**: Only two languages are supported in the Tuquet Admin platform:
  - `en-US`: English (Canonical Default)
  - `vi-VN`: Tiếng Việt (Vietnamese)
- **Default Locale**: Always initialize and default to `en-US`. If no explicit choice exists in `localStorage` (`preferences-locale`), the app MUST render in `en-US`.

## 2. Two-Tier Localization Architecture
- **Framework Core Tier (`admin/packages/locales/src/langs/`)**:
  - Contains shared system labels: `common.json`, `authentication.json`, `preferences.json`, `profile.json`, `ui.json`.
  - Both `en-US` and `vi-VN` MUST mirror each other with 100% key parity.
- **Business App Tier (`admin/apps/web-admin/src/locales/langs/`)**:
  - Contains view and route-specific labels: `page.json`.
  - Both `en-US` and `vi-VN` MUST maintain identical JSON tree structures.

## 3. Strict Prohibitions (Zero Hardcoding)
- **Zero Raw Strings in UI**: NEVER hardcode raw text strings directly in `.vue` templates or script toast notifications (e.g. `<button>Ghép Nối</button>` or `toast.success("Thành công")`).
- **Always invoke `$t`**:
  - In template: `{{ $t('page.workspace.title') }}` or `:placeholder="$t('common.actions.search')"`
  - In script setup: `import { $t } from '#/locales'; toast.success($t('page.workspace.create_success'))`

## 4. Key Taxonomy Standard
- Format: `[scope].[domain].[component_or_entity].[element_type]` in `snake_case`.
  - Examples:
    - `$t('common.actions.create')`
    - `$t('common.status.online')`
    - `$t('page.fleet.devices.title')`
    - `$t('page.workspace.current_active')`

## 5. Technical Terminology Policy
- Technical terms (e.g. `Multi-Tenant`, `SSO`, `Loopback Daemon`, `Runner`, `Bridge`, `Proxy`, `IP`, `CDN`, `Active`, `Online`, `Offline`) SHOULD retain their internationally recognized standard terms even within Vietnamese localization for clarity and operator consistency.
